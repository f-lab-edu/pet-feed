# 2026-11-12 작업 기록

## DB 영속화

- 회원·게시글·댓글·팔로우·미디어의 기본 DB를 서비스별 H2 파일 DB로 변경했다. 각 서비스의 환경 변수로 절대 경로를 지정할 수 있다.
- Flyway V1 마이그레이션으로 테이블·인덱스·제약 조건을 관리하고 Hibernate는 `validate`로 스키마만 검증한다.
- 일반 테스트는 고유 메모리 DB로 격리했다. 재시작 테스트 5개는 임시 파일 DB에 저장한 후 컨텍스트와 커넥션 풀을 종료하고 같은 DB로 다시 시작한다.
- 미디어 바이트·Range·소유권, 게시글 첨부 순서·삭제 상태·댓글 정리 실패 이력 및 재시도 완료 상태, 댓글 닫힘 상태, 회원 탈퇴 상태, 팔로우 관계의 보존을 검증했다.
- 실행 위치별 DB 경로, 마이그레이션 추가 방법, 기존 메모리 데이터 이관 제한, 백업 범위를 [로컬 DB 영속화](database-persistence.md)에 정리했다.
- 기존 작업 중인 미디어 컨트롤러 변경과 Microsoft/ 폴더는 수정하지 않았다.

## 공통 계약 모듈과 회원 명칭 정리

- 공통 엔티티·업무 규칙이 없는 `common-domain`을 `api-contracts`로 변경하고 패키지를 `com.petfeed.contracts`로 옮겼다. DTO·헤더 계약만 공유하며 프록시용 `DownstreamException`은 Gateway로 옮겼다.
- `user-service` → `member-service`, `com.petfeed.user` → `com.petfeed.member`로 변경했다. 서비스·Facade·Feign·DTO·JWT·저장소의 회원 관련 Java 명칭을 `Member`, `memberKey`, `members`로 통일했다.
- 외부 API의 `/users`, `userKey`, `users`, `X-User-Key`는 호환성을 유지한다. DTO에는 명시적 JSON 매핑을 추가했다. 과거 날짜별 기록은 당시 명칭을 보존한다.
- 기존 회원 DB 디렉터리는 새 모듈과 함께 이동했다. 파일명 `userdb`와 컬럼 `user_key`, V1 SQL은 보존한다. `MEMBER_DB_URL`을 우선 사용하며 `USER_DB_URL`도 지원한다.
- 회원 JSON 호환성 테스트에서 `following` 역직렬화 누락을 발견해 `MemberSummary`와 `MemberProfileResponse`에 명시적 매핑을 추가했다.
- 모든 백엔드 모듈 테스트 및 계약 테스트 총 107개가 실패·오류 없이 통과했고, 7개 서비스의 bootJar 빌드도 성공했다. 실제 서버를 재기동한 것은 아니다.
- 실행 명령은 `.\gradlew.bat :member-service:bootRun`이다. IDE에서는 Gradle 프로젝트를 다시 불러오고 메인 클래스를 `com.petfeed.member.MemberServiceApplication`으로 지정한다. 이전 명칭의 JAR는 혼동 방지를 위해 `build/legacy-naming-artifacts`로 이동했다.

## 리뷰 후 도메인·API 경계 수정

- DTO 공유는 유지한다. 제공자·소비자에 같은 DTO를 복제하지 않고 회원 기본 정보와 외부 집계 프로필처럼 역할이 다른 계약만 분리했다.
- 회원 엔티티는 자체 `com.petfeed.member.domain.MemberStatus`를 사용한다. API 계약의 `AuthorStatus`는 서비스에서 switch로 명시적으로 변환한다.
- 회원 서비스는 `MemberInfoResponse`로 닉네임·프로필 이미지·소개만 반환한다. Facade의 `MemberFacade`가 게시글 수와 `FollowStatistics`를 조합해 최종 `MemberProfileResponse`를 생성한다. 중간 프로필에 가짜 집계값을 넣지 않는다.
- 사용자 요청에 따라 외부 계약도 `/members`, `memberKey`, `members`, `X-Member-Key`로 변경했다. 기존 별칭은 제공하지 않는다. Feign·Gateway·HTTP 예제·화면 API 참조·스모크 스크립트도 갱신했다. 로그인 `/api/v1/auth/login` 및 기존 DB 파일·컬럼은 유지한다.
- 전체 백엔드 테스트와 JSON 계약 테스트 108개가 실패·오류 없이 통과했다. JS 및 미디어 스모크 스크립트 문법 검사도 통과했다. 실제 서비스 실행은 하지 않았다.
- 기존 DB 영속화, 모듈·명칭 정리, 도메인·API 경계 변경, following 역직렬화 수정을 별도 커밋으로 분리한다. 이전 닉네임 화면 수정과 기존 미디어 컨트롤러 공백 변경은 이 커밋들에 섞지 않는다.
