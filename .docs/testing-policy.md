# 테스트 책임 정책

- 작성일: 2026-10-22
- 목적: Facade와 각 서비스의 책임 경계에 맞춰 테스트를 배치한다.

## 기본 원칙

각 구성 요소는 자신이 소유한 규칙과 동작의 테스트를 책임진다. 유닛 테스트는 각 서비스에만 한정하지 않으며, Facade와 통신 어댑터에도 검증할 독립 로직이 있으면 작성한다.

| 대상 | 유닛 테스트 | 추가 검증 |
| --- | --- | --- |
| 각 서비스 | 도메인 규칙, 권한 판단, 상태 전환, 중복·없는 데이터 처리 | 실제 DB의 제약과 트랜잭션은 통합 테스트로 검증 |
| Facade | 호출 순서, 독립 작업의 조합, 완료 조건, 필수·선택 호출의 실패 대응 | 병렬 실행·타임아웃·부분 성공·복구는 제어 가능한 대역과 통합 테스트로 검증 |
| Feign 어댑터 | 직접 작성한 변환·오류 매핑 로직 | HTTP 경로·헤더·직렬화·상태 코드 매핑은 WireMock 등으로 검증 |
| Gateway | 직접 작성한 토큰·헤더 처리 로직 | 인증 정책, 필터 체인, 프록시 전달은 보안·HTTP 통합 테스트로 검증 |
| 서비스 간 API | 각 소유 구성 요소의 로직을 독립 검증 | 소비자와 제공자의 API 계약 및 주요 E2E 흐름 검증 |

## 책임 경계

- Facade 테스트에서 회원·게시물의 모든 업무 규칙을 재검증하지 않는다. 각 서비스의 API 계약이 지켜진다는 전제로 호출 조정과 응답 정책을 검증한다.
- 각 서비스의 유닛 테스트는 다른 서비스를 실제로 기동하지 않는다. 이번 설계 방향에서 서비스 간 외부 호출은 Facade가 조정한다.
- 목으로 성공 결과를 반환하도록 설정한 테스트만으로 실제 API 계약이나 데이터 일관성이 보장됐다고 판단하지 않는다.
- 같은 입력을 여러 계층에서 기계적으로 반복 검증하기보다 각 계층이 소유한 실패 원인을 검증한다.
- 분산 쓰기는 일부 성공, 응답 유실, 재시도, 중복 요청, 보상 실패 이후의 상태까지 검증한다. 오류 응답만 확인하는 것으로 복구 검증을 대신하지 않는다.

## 탈퇴 정책에 적용할 예

- user-service: 탈퇴 상태 전환, 로그인 거부, 회원 레코드 보존을 검증한다.
- post-service: 게시물과 작성자 식별 관계가 보존되는지 검증한다.
- Facade: 작성자 상태를 조합해 `(탈퇴한 회원)`을 제공하고, 회원 조회 실패를 탈퇴 상태로 오인하지 않는지 검증한다.
- API 계약·E2E: 상태 필드와 표시용 이름이 실제 응답으로 전달되는지 검증한다.

이 문서는 검증 책임의 기준이며, 위 테스트가 모두 구현되었다는 의미는 아니다. 현재 실행 결과는 날짜별 기록에서 별도로 관리한다.
