# 2026-10-30 개발 상태

## 팔로우 도메인 구현

- `follow-service` Gradle 모듈과 독립 애플리케이션·DB·포트 8085를 추가했다.
- `follows` 테이블, 방향성 관계, 복합 유니크 제약, 자기 팔로우 CHECK, 양방향 조회 인덱스를 구성했다.
- 팔로우·언팔로우 및 커서 목록과 요청자 기준 팔로우 여부 조회를 구현했다. 중복 생성은 409, 자기 팔로우는 400, 없는 관계의 언팔로우는 성공이다.
- Facade의 기존 팔로우 API를 신규 서비스로 연결하고 기존에 누락된 요청자 키를 전달하도록 수정했다. user-service로 잘못 전달하던 팔로우 Feign 계약을 제거했다.
- 회원 존재·정상 상태를 Facade에서 검사하며 회원 프로필의 팔로워·팔로잉 수와 following 여부를 실제 값으로 조합한다.
- 탈퇴 관계는 저장소에 보존하고 목록·집계에서는 제외한다. 탈퇴 회원으로 원본 페이지가 채워진 경우도 다음 정상 회원을 찾아 외부 페이지를 구성한다.
- [팔로우 도메인 명세](follow-domain.md)에 API, 삭제·탈퇴 정책, 조회 비용과 일관성 한계를 기록했다. 기존 명세 및 여섯 서비스 실행 안내도 갱신했다.

## 한계와 후속 작업

- 집계 시 관계를 전부 순회하고 상대 회원 상태를 확인한다. 대규모 데이터 대응에는 회원 상태 일괄 조회/이벤트 투영과 집계 최적화가 필요하다.
- 회원 상태 검사와 관계 생성은 분산 원자성을 보장하지 않는다. 탈퇴 직후 기존 관계는 조회 시 제외된다.
- H2 메모리 DB를 유지하며 운영 영속화, 전체 서비스·브라우저 E2E, 팔로우 화면은 별도 작업이다.
- follow-service 실행: `.\gradlew.bat :follow-service:bootRun`. 실제 API 모드에는 Gateway·Facade·user·post·comment·follow 총 여섯 서비스가 필요하다.

## 검증

- `.\gradlew.bat :follow-service:test :facade:test :user-service:test :post-service:test :comment-service:test :api-gateway:test --console=plain` → BUILD SUCCESSFUL.
- follow-service 4개, Facade 50개, 회원 19개, 게시물 6개, 댓글 5개, Gateway 2개로 총 86개 실패/오류 0이다.
- 독립 DB에서 팔로우·언팔로우, 중복·자기 팔로우, 동시 중복 요청의 유니크 제약, 양방향 커서와 팔로우 여부 일괄 조회를 검증했다.
- Facade에서 정상 회원 검사·요청자 키 전달, 탈퇴 대상 언팔로우, 여러 원본 페이지에 걸친 탈퇴 회원 필터링·커서, 정상 회원 관계 수와 요청자 following 여부를 검증했다. 기존 컨트롤러 HTTP 테스트도 새 내부 계약과 요청자 헤더를 확인하도록 갱신했다.
- 기존 회원 계약 테스트에서 재발한 502에 대해 테스트 전용 Feign `Connection: close` 설정을 추가했다. WireMock 요청 로그에서 헤더를 확인했고 최종 전체 실행은 통과했다. 운영 HTTP 연결 설정은 변경하지 않았다.
- `git diff --check` 통과. 전체 실제 서버·브라우저 E2E와 운영 DB는 이번 검증에 포함하지 않는다.
