# 회원 탈퇴 및 게시물 작성자 표시 정책

- 작성일: 2026-10-22
- 상태: 회원 상태 전환 및 회원별 게시물 목록 작성자 응답 구현, 게시물 상세·저장 기능 미구현

## 확정 정책

1. 회원이 탈퇴해도 이전에 작성한 게시물은 삭제하지 않는다.
2. 회원 탈퇴 시 회원 데이터를 물리적으로 삭제하지 않는다. 회원 레코드를 유지하고 탈퇴 상태로 전환한다.
3. 탈퇴한 회원이 작성한 게시물에는 작성자를 `(탈퇴한 회원)`으로 표시한다. 화면이 탈퇴 여부를 판단할 수 있도록 작성자 상태를 응답 모델에 포함한다.

## 회원과 게시물의 상태

- 탈퇴는 회원의 상태 변경으로 처리하는 소프트 삭제다.
- 게시물의 작성자와 회원을 연결하는 식별 관계를 유지한다.
- 회원 탈퇴 처리에서 게시물 삭제를 호출하거나 연쇄 삭제를 수행하지 않는다.
- 기존의 탈퇴 후 로그인 불가 규칙은 유지한다. 회원 레코드가 존재하더라도 탈퇴 상태이면 로그인을 허용하지 않는다.
- 작성자를 조회할 때 탈퇴한 회원과 존재하지 않는 회원을 구분할 수 있어야 한다. 회원 조회에 일괄적인 탈퇴 회원 제외 필터를 적용해 작성자 상태를 잃지 않도록 한다.
- 일반 회원 프로필의 공개 범위와 내부 작성자 상태 조회는 별도로 정의한다. 회원 레코드 보존이 개인정보의 외부 노출을 의미하지는 않는다.

## 화면에 전달할 작성자 모델

화면 표시 문구를 회원의 실제 닉네임에 덮어쓰지 않는다. 응답의 작성자 모델에 탈퇴 상태와 표시용 이름을 표현한다.

회원별 게시물 목록의 각 `PostSummary`에 다음 `author` 모델을 포함한다. 게시물 상세는 구현 시 같은 모델을 사용한다.

| 필드 | 의미 | 탈퇴 회원 예시 |
| --- | --- | --- |
| `author.status` | 작성자의 회원 상태 | `WITHDRAWN` |
| `author.displayName` | 화면에 표시할 작성자 이름 | `(탈퇴한 회원)` |

```json
{
  "postId": 1,
  "author": {
    "status": "WITHDRAWN",
    "displayName": "(탈퇴한 회원)"
  }
}
```

- 게시물 목록과 상세에서 동일한 작성자 표시 정책을 적용한다.
- 화면은 이름 문자열을 비교해서 탈퇴 여부를 추측하지 않고 명시적인 상태를 사용한다.
- 회원 서비스 통신 실패나 타임아웃을 탈퇴 상태로 간주하지 않는다. 상태 조회 실패 시 응답 정책은 별도로 정한다.

## 책임 분담

| 구성 요소 | 책임 |
| --- | --- |
| user-service | 회원 탈퇴 상태 저장, 로그인 제한, 내부 작성자 상태 제공 |
| post-service | 게시물과 작성자 식별 관계 보존, 회원 탈퇴에 따른 게시물 삭제 금지 |
| Facade | 게시물과 회원 상태의 조회 조정, 외부 응답의 작성자 모델 조합 |
| 화면 | 응답의 작성자 상태·표시용 이름을 이용해 `(탈퇴한 회원)` 표시 |

이번 정책에서는 회원 탈퇴 성공 조건에 게시물 삭제 완료를 포함하지 않는다. 실제 탈퇴 상태 저장과 인증·조회에 반영되는 시점은 후속 설계에서 명확히 한다.

## 구현 시 검증할 시나리오

1. 탈퇴 후에도 회원 레코드가 남고 상태가 탈퇴로 변경된다.
2. 탈퇴 후 해당 회원의 기존 게시물과 작성자 식별 관계가 유지된다.
3. 탈퇴 후 로그인이 거부된다.
4. 탈퇴 회원의 게시물 목록과 상세 응답에 탈퇴 상태와 `(탈퇴한 회원)` 표시용 이름이 포함된다.
5. 정상 회원은 정상 상태와 표시용 이름으로 응답된다.
6. 회원 상태 조회 실패를 탈퇴 회원으로 잘못 표시하지 않는다.

## 현재 구현과의 차이 및 미결정 사항

- 회원 탈퇴는 `Member.status`를 `ACTIVE`에서 `WITHDRAWN`으로 바꾸며 회원 레코드와 닉네임을 보존한다. 탈퇴 트랜잭션 커밋 후 새 로그인은 401로 거부한다.
- `GET /internal/v1/users/{user-key}/author`는 정상·탈퇴 회원의 상태와 표시용 이름만 제공하며 없는 회원은 404로 구분한다. Facade는 회원별 게시물 목록에 이 결과를 조합한다. 조회 실패는 기존 하위 서비스 오류 처리로 전파하고 탈퇴 상태를 만들지 않는다.
- 이번 구현은 기존 동작을 유지하는 기준으로 탈퇴 회원의 공개 프로필·수정·반복 탈퇴를 404로 처리하고 이메일 유니크 제약을 유지한다. 탈퇴 이메일로 재가입은 409다. 이메일 재사용 정책을 바꾸려면 별도 결정이 필요하다.
- 기발급 JWT의 즉시 폐기는 구현하지 않았다. 저장된 탈퇴 상태를 확인하는 회원 수정은 차단되지만, 다른 기능의 JWT 처리 정책은 후속 설계가 필요하다.
- post-service는 아직 애플리케이션 뼈대만 있어 게시물 저장·상세와 실제 데이터 보존의 통합 검증은 후속 작업이다. 탈퇴는 게시물 서비스를 호출하지 않는다.
- 회원 상태 변경과 작성자 조회 사이의 최신성 보장, 캐시 무효화 및 기존 게시물의 작성자 식별자 보유 여부를 확인해야 한다.
- 보존할 개인정보의 범위·마스킹·익명화·보존 기간은 이 문서에서 확정하지 않는다.

검증 결과와 구현 한계는 날짜별 기록에서 관리한다.
